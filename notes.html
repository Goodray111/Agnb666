Notes from building this

Three short entries about the work behind these pages: what I tried, what broke, and what I would do differently. Together with the Git history, this is the honest record of the build.

8 November · entry 1

Starting with the navigation, not the hero

navigation process

The first version had four pages and four copies of the same navigation. Every time I changed a link I had to remember three other files. So before touching the design, I moved the navigation into nav.html and wrote nav.js to fetch it into every page.

It was the smallest change that removed a whole class of bugs. The lesson was not “use JavaScript”. The lesson was that repetition is a bug waiting to happen.

9 November · entry 2

Eighteen quotes, one search box

javascript filtering

I could have written the quotes straight into the HTML and called it done. Filtering them showed me why the markup should be the data: the search box reads the same elements that the page already displays, so there is no second copy of the list to keep in sync.

The first version filtered by exact case and missed “Web” when I typed “web”. Normalising both sides with toLowerCase() fixed it. Then the theme chips did nothing, because the buttons said The Web but the cards stored the-web — a hyphen, one attribute, twenty minutes.

10 November · entry 3

The bug game, and the bug in the bug game

game testing

The game looked finished long before it was. Three problems only showed up when I played it:

  1. The bug could appear half outside the field, because I used random pixels instead of percentages.
  2. Stopping the game left the countdown running — I cleared one timer and forgot the other.
  3. Clicking “Stop” then “Start” again added a second interval, so the clock counted down twice as fast.

All three are the same kind of mistake: state that lives in two places. The fix was to clear every timer when the game ends or restarts, and to keep the score, the clock and the running flag in one object.

Reading time: 2 min

What comes next

Small things I still want to add, in the order I would do them.

  1. Move the quotes into a JSON file. Then adding a quote is one line, not one more block of HTML.
  2. A proper 404 page. GitHub Pages serves its own; mine could point back to the four real pages.
  3. Test with a screen reader. I have only tested with a keyboard so far.
